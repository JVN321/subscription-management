# Database: PostgreSQL 16 & Drizzle ORM

> **Status: Confirmed Architecture**
>
> Relational persistence standards, Drizzle ORM configuration, migration ownership, and connection pooling rules for `packages/db`.

---

## 1. Role & Technology Overview

PostgreSQL 16 serves as the single authoritative source of truth for all business data. **Drizzle ORM** provides a lightweight, type-safe SQL layer that maps 1:1 to SQL without the heavy binary runtime overhead of Prisma or the magic decorator complexity of TypeORM.

Key Principles:
- **Zero Raw Mutations**: Every table has a declared Drizzle TypeScript schema in `packages/db/src/schema/`.
- **Committed Migrations**: All database schema changes are managed via version-controlled SQL migration files generated by `drizzle-kit`.
- **Explicit Transactions**: All multi-table updates must use `db.transaction(async (tx) => { ... })`.

## 3. Migration Workflow & Tooling

```bash
# Generate a new migration after editing schema files:
pnpm --filter @repo/db db:generate

# Apply pending migrations to the PostgreSQL database:
pnpm --filter @repo/db db:migrate

# Open Drizzle Studio to inspect local database state:
pnpm --filter @repo/db db:studio
```

## 4. Connection Pool Configuration

The database client utilizes `postgres` (or `pg`) with connection pooling optimized for containerized workloads:
```typescript
import { drizzle } from 'drizzle-orm/postgres-js';
import postgres from 'postgres';
import * as schema from './schema';

const connectionString = process.env.DATABASE_URL!;
const client = postgres(connectionString, {
  max: process.env.DB_POOL_MAX ? parseInt(process.env.DB_POOL_MAX) : 20,
  idle_timeout: 30,
  connect_timeout: 10,
  prepare: true
});

export const db = drizzle(client, { schema });
```
